# 구현 기록

왜 지금처럼 만들었는지의 기록입니다: "~이라서 ~로 만들었다".
기능을 새로 만들 때는 읽지 않습니다. **이미 있는 코드를 바꾸기 전에**, 그 코드 주석이 가리키는 절을 여기서 찾아 읽고 적힌 전제가 지금도 맞는지 봅니다. 전제가 바뀌었으면 코드도 바꿔도 됩니다.
절 제목은 코드 주석이 가리키는 문서와 절 이름입니다 (예: 주석 `// docs/FEATURES.md: 재생` → 절 `FEATURES.md: 재생`).

## PROTOCOL.md: 찾기
- Windows는 광고 주소를 바꿔서 확인 전에 끊긴 주소는 이미 바뀌었을 수 있다. 그래서 후보 기억을 이번 듣기 동안만 하게 만들었다.
- Windows 광고 시작 결과는 나중에 상태로만 알 수 있고, 시작 직후 잠깐 `Aborted`로 보였다가 `Started`로 바뀌기도 했다. 그래서 2초까지 상태를 끝까지 지켜보게 만들었다.

## PROTOCOL.md: 연결
- PC는 구독을 받자마자 문제를 보내서, 그게 폰의 구독 완료 신호(`onDescriptorWrite`)보다 먼저 올 수 있었다 (2026-10-07: 다시 연결 때 가끔 5초 뒤 확인 실패). 그래서 폰이 구독 전에 확인 준비(`Auth`)를 끝내게 만들었다.
- Windows는 끝났다는 알림(`deferral.Complete()`)이 없으면 쓰기 요청을 붙잡고 있어서, 실패할 수 있는 부분을 클로저로 감싸고 그 뒤에 항상 `Complete()`를 부르게 만들었다.
- `IBuffer`는 `Send`가 아니어서 await 전에 버리게 만들었다.

## PROTOCOL.md: 제어 메시지
- 소켓에 쓴 패킷이 실제 전파로 나가기 전에 정리하면 폰이 중지를 못 받고 "끊김"으로 봐서, 중지 패킷을 쓴 뒤 0.2초 더 쉬게 만들었다.
- 그냥 drop하면 폰은 연결이 끊긴 줄 알고 다시 찾아서, `stop()`으로 중지를 먼저 알리고 drop하게 만들었다.

## PROTOCOL.md: 연결 확인
- PC는 5초를 기다리므로, 폰은 여유를 두어 10초로 만들었다.
- 옛 PC 앱은 문제를 보내지 않아서, 10초가 지나면 그 PC를 다음 후보로 넘기게 만들었다.
- 비교에 걸리는 시간으로 답이 새지 않게, 증명 비교를 PC는 `verify_slice`, 폰은 `MessageDigest.isEqual`로 만들었다.
- Windows는 구독이 끊긴 폰의 작업을 중간에 끊어서(abort), 청취자 수를 `Drop`으로 빼게 만들었다 (그래야 끊겨도 수가 남지 않음).

## PROTOCOL.md: 잠그기
- 순번을 되돌리면 같은 번호를 다시 쓰게 돼서, PC의 긴 순번을 u64로 두고 늘리기만 하게 만들었다 (u64라 사실상 돌지 않음).

## CODECS.md
- 프레임 하나를 둘로 쪼개 보내면 디코더가 못 풀어서, 프레임 하나 = 패킷 하나로 만들었다.
- MediaCodec Opus 디코더는 첫 출력을 바로 꺼내면 출력이 한 패킷씩 밀렸다. 그래서 첫 출력은 조금(5ms) 기다리게 만들었다.
- MediaCodec 문서의 Opus 설정값을 따라 csd-0 = OpusHead(RFC 7845 5.1, 19바이트), csd-1 = pre-skip ns(0), csd-2 = seek pre-roll ns(80ms)로 넣었다.

## CODECS.md: 코덱 바꾸는 법
- 디코더를 못 여는 경우(기기에 Opus 디코더가 없음 등)를 따로 나누지 않고 "모르는 코덱"으로 보이게 만들었다. 원인은 logcat에 남긴다.

## FEATURES.md: 인코딩
- 코덱 고르는 쪽(watch 통로)이 사라지면, 멈추지 않고 지금 코덱을 그대로 쓰게 만들었다.

## FEATURES.md: 공유
- BLE가 먼저 멈춰야 해서, 공유 상태(`Sharing`)의 필드 순서(= drop 순서)를 BLE 먼저로 만들었다.

## FEATURES.md: PC 화면
- WebKitGTK(Linux)는 기본 `select`를 GTK 모양(밝은 바탕)으로 그려서, `appearance-none`으로 끄고 ▼를 직접 그렸다.
- 가로 화면을 정확히 가운데에 두면 처져 보여서, 아래 여백을 더 줘 살짝 위로 올렸다.
- 공유를 켜고 끌 때 화면이 움직이지 않게, QR이 없을 때도 자리를 남겼다.

## FEATURES.md: 업데이트
- PC 설치 프로그램이 앱을 바로 끝낼 수 있어서, 설치 전에 공유 중지를 먼저 알리게 만들었다.
- 사이드로드 앱은 조용히 설치할 수 없어서, 안드로이드 설치 확인 화면을 띄우게 만들었다. 사용자가 취소해도 실패 결과로 와서 알림을 띄운다.

## FEATURES.md: 재생
- 기기가 주는 AudioTrack 최소 버퍼(S25는 120ms)가 크고 기기가 그보다 작게 만들어 주지 않아서, 만든 뒤 실제로 쓰는 양만 40ms로 줄였다.

## FEATURES.md: 알림음
- 딸깍 소리를 막으려고 앞뒤 5ms에 걸쳐 커지고 작아지게 만들었다.
- 서비스가 먼저 끝나도 소리를 끝까지 내려고, 재생 뒤 정리를 두 음 + 0.2초 뒤로 미뤘다.

## FEATURES.md: 폰 화면
- 화면 회전 등으로 QR 링크가 다시 처리되지 않게, 처리한 뒤 링크를 지우게 만들었다.
- 조각 양 끝에서 가짜 주파수가 생겨서 비주얼라이저에 Hann 창을 씌웠다. 최대 크기 사인파가 0 dB가 되도록 크기를 n/4로 나눴다.
- 설치 확인 화면에서 취소하고 돌아오면 버튼을 다시 누를 수 있게, 화면에 돌아올 때 업데이트 버튼을 되살리게 만들었다.
