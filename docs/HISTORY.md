# 시행착오 기록

코드 주석에서 옮긴 함정·이유입니다. **평소엔 읽지 않습니다.** 그 절의 코드를 고칠 때만 같은 이름의 절을 찾아봅니다.
절 제목은 그 내용이 걸린 문서와 절 이름입니다 (예: `FEATURES.md: 재생`).

## PROTOCOL.md: 찾기
- 확인 전에 연결이 끊긴 주소는 이미 바뀌었을 수 있습니다 (Windows는 광고 주소를 바꿈). 그래서 후보 기억은 이번 듣기 동안만 합니다.

## PROTOCOL.md: 연결
- PC는 구독을 받자마자 문제를 보내고, 그게 폰의 구독 완료 신호(`onDescriptorWrite`)보다 먼저 올 수 있습니다. 그래서 폰은 구독 전에 확인 준비(`Auth`)를 끝냅니다. (2026-10-07: 다시 연결 때 가끔 5초 뒤 확인 실패)

## PROTOCOL.md: 제어 메시지
- 중지 패킷을 쓰고 0.2초 더 쉬는 건, 소켓에 쓴 패킷이 실제 전파로 나갈 시간입니다. 바로 정리하면 폰이 중지를 못 받고 "끊김"으로 봅니다.
- 그냥 drop하면 폰은 연결이 끊긴 줄 알고 다시 찾습니다. 그래서 `stop()`을 먼저 부르고 drop합니다.

## PROTOCOL.md: 연결 확인
- 폰의 10초 = PC의 5초에 여유를 둔 값.
- 옛 PC 앱은 문제를 보내지 않으므로 10초가 지나면 그 PC는 다음 후보로 넘깁니다.
- 증명 비교는 걸리는 시간으로 답이 새지 않게 PC는 `verify_slice`, 폰은 `MessageDigest.isEqual`.

## PROTOCOL.md: 잠그기
- PC의 긴 순번은 u64라 사실상 돌지 않습니다. 되돌리면 같은 번호를 다시 쓰게 되므로 늘리기만 합니다.

## FEATURES.md: 인코딩
- 코덱 고르는 쪽(watch 통로)이 사라지면 지금 코덱을 그대로 씁니다.
- 프레임 하나를 둘로 쪼개 보내면 디코더가 못 풉니다. 그래서 프레임 하나 = 패킷 하나.

## FEATURES.md: 공유
- 광고 시작 결과는 나중에 상태로만 알 수 있습니다. 시작 직후 잠깐 `Aborted`로 보였다가 `Started`로 바뀌기도 해서 2초까지 끝까지 지켜봅니다.
- 쓰기 요청은 중간에 실패해도 `deferral.Complete()`를 불러야 Windows가 요청을 붙잡고 있지 않습니다.
- `IBuffer`는 `Send`가 아니라서 await 전에 버립니다.
- Windows는 구독이 끊긴 폰의 작업을 중간에 끊습니다(abort). 그래서 청취자 수는 `Drop`으로 빼야 남지 않습니다.
- 공유 상태의 필드 순서 = drop 순서. BLE가 먼저 멈춰야 합니다.

## FEATURES.md: PC 화면
- WebKitGTK(Linux)는 기본 `select`를 GTK 모양(밝은 바탕)으로 그려서 `appearance-none` + ▼를 직접 그립니다.
- 가로 화면을 정확히 가운데에 두면 처져 보여서 아래 여백을 더 줍니다.
- QR 자리를 남기는 건 공유를 켜고 끌 때 화면이 움직이지 않게 하려는 것.

## FEATURES.md: 업데이트
- PC 설치 프로그램이 앱을 바로 끝낼 수 있어서 설치 전에 공유 중지를 먼저 알립니다.
- 사이드로드 앱은 조용히 설치할 수 없어 안드로이드가 설치 확인을 묻습니다. 사용자가 취소해도 실패 결과로 옵니다.
- 설치 확인 화면에서 취소하고 돌아오면 버튼을 다시 누를 수 있게 화면에 돌아올 때 버튼을 되살립니다.

## FEATURES.md: 재생
- MediaCodec Opus 디코더는 첫 출력을 조금(5ms) 기다려야 합니다. 안 기다리면 출력이 한 패킷씩 밀립니다.
- MediaCodec Opus 설정값: csd-0 = OpusHead(RFC 7845 5.1, 19바이트), csd-1 = pre-skip ns(0), csd-2 = seek pre-roll ns(80ms).
- 기기가 주는 AudioTrack 최소 버퍼(S25는 120ms)는 큽니다. 기기가 그보다 작게 만들어 주지 않아서, 만든 뒤 실제로 쓰는 양만 40ms로 줄입니다.
- 디코더를 못 여는 경우(기기에 Opus 디코더가 없음 등)도 "모르는 코덱"으로 보입니다. 원인은 logcat.

## FEATURES.md: 알림음
- 앞뒤 5ms 커지고 작아지는 건 딸깍 소리를 막으려는 것.
- 재생 뒤 정리를 두 음 + 0.2초 뒤로 미루는 건, 서비스가 먼저 끝나도 소리를 끝까지 내려는 것.

## FEATURES.md: 폰 화면
- QR 링크로 연 화면은 처리 뒤 링크를 지웁니다. 화면 회전 등으로 다시 처리되지 않게.
- 비주얼라이저의 Hann 창은 조각 양 끝에서 생기는 가짜 주파수를 막습니다. 최대 크기 사인파가 0 dB가 되도록 크기를 n/4로 나눕니다.
