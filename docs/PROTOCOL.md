# PC ↔ 폰 약속 (BLE 프로토콜)

PC(`src-tauri/`)와 폰 앱(`android/`)이 서로 맞춰야 하는 값은 전부 여기에 적습니다.
한쪽을 바꾸면 이 문서와 반대쪽 코드를 같이 바꿉니다. 코덱 번호 표는 [CODECS.md](CODECS.md).

| 값이 있는 곳 | PC | 폰 |
|---|---|---|
| UUID·광고 | `src-tauri/src/ble.rs` | `Protocol.kt` |
| 패킷 헤더·제어 메시지 | `src-tauri/src/codec/packet.rs` | `Protocol.kt` |
| 코덱 번호 | `src-tauri/src/codec/mod.rs` | `Codecs.kt` |

## 1. 찾기: 광고와 QR

| 항목 | 값 |
|---|---|
| 서비스 UUID | `5e7a0001-3c1b-4f6e-9d2a-7b1c0e5a9f10` |
| 오디오 특성 UUID (Notify) | `5e7a0002-3c1b-4f6e-9d2a-7b1c0e5a9f10` |
| 광고 제조사 ID | `0xFFFF` (테스트/미등록용 예약 ID) |
| 광고 제조사 데이터 | PC 고유 번호 4바이트 |
| QR 링크 | `hearone://connect?id=<PC 번호 16진수 8자리>&name=<PC 이름>` |

- PC 고유 번호는 처음 실행할 때 무작위로 만들어 설정 폴더(`device_id`)에 저장합니다. 다시 켜도 같습니다.
- `name`은 PC 컴퓨터 이름(hostname)을 URL 퍼센트 인코딩(UTF-8)한 값입니다. 광고에는 자리가 없어 QR에만 싣습니다. 폰은 처음 저장할 때만 쓰고 연결은 번호로 합니다. `name`이 없는 링크도 읽습니다.
- 광고는 31바이트 제한: flags(3) + 128bit UUID(18) + 제조사 데이터(4+4) = 29바이트. 기기 이름은 못 넣습니다.
- 폰은 서비스 UUID + 제조사 데이터(PC 번호)가 맞는 광고만 찾습니다. 기록에 없는 PC는 찾지 않으므로 처음 연결은 QR로 합니다.

## 2. 연결

1. 폰이 연결 → MTU 517 요청 → 서비스 찾기
2. 폰이 오디오 특성의 표준 CCCD(`00002902-0000-1000-8000-00805f9b34fb`)에 알림 켜기를 씀 = 구독
3. PC는 구독한 폰마다 Notify로 패킷을 계속 보냄
4. 페어링·암호화는 하지 않습니다 (특성에 보안 설정 없음)

## 3. 패킷

Notify 하나 = 패킷 하나. 최대 크기 = MTU − 3 (ATT 헤더), 20~512바이트로 제한.

| 바이트 | 내용 |
|---|---|
| `[0]` | 버전 = `1` |
| `[1]` | 코덱 번호 ([CODECS.md](CODECS.md)). **`0` = 제어 메시지** |
| `[2..4]` | 순번 u16 little-endian. 폰마다 따로 0부터 세고 65535 다음은 0. 손실 감지용 |
| `[4..]` | 코덱 데이터. 제어 메시지면 명령 1바이트 |

- 패킷 하나에 코덱 프레임 하나. 프레임이 MTU보다 크면 보내지 않고 버립니다.
- 버전이 다르거나 헤더보다 짧은 패킷은 폰이 버립니다.

## 4. 제어 메시지 (코덱 번호 0)

| 명령 `[4]` | 뜻 | 폰 동작 |
|---|---|---|
| `1` | PC가 공유를 중지함 (공유 중지 버튼, 창 닫기) | 정지 버튼을 누른 것과 같이 멈춤. 다시 찾지 않음 |

- 소리 패킷과 같은 통로로 보내므로 마지막 소리 뒤에 도착합니다.
- PC는 중지 패킷을 보낸 뒤 최대 0.5초 기다리고 0.2초 더 쉰 다음 연결을 정리합니다.
- 강제 종료·PC 꺼짐처럼 중지 패킷을 못 보내면 폰은 "끊김"으로 보고 다시 찾습니다.
